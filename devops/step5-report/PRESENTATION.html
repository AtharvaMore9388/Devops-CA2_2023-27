05 / 05
Reflection
Challenges & Lessons Learned
Real-world problems solved during the DevOps implementation
⚡ Challenges & Solutions
🔥
torch not found in venv
Used system Python; documented correct environment activation
⏰️
ML inference takes 30–60 seconds
Set Nginx & Gunicorn timeout to 300s to prevent gateway errors
💾
Large model files (GBs) bloating Docker image
Used PersistentVolumeClaims — model weights never baked into image
🏗️
face_recognition (dlib) compile time 20+ min
Pre-built in Docker builder stage with cmake; cached in layer
🔧
MAE weights missing — silent warning
Graceful fallback to OpenCV inpainting; no crash on missing weights
🔴
maxUnavailable > 0 caused brief downtime
Changed to maxUnavailable: 0 — true zero-downtime rolling deploys
🎓 Lessons Learned
  • 🐳
    Containers ≠ Silver Bullet — ML model weights must be mounted via volumes, not baked into Docker images
  • ⚖️
    K8s Probe Timing — initialDelaySeconds must account for ML model loading (60s+)
  • ⚙️
    Ansible Idempotency — Eliminates manual errors during iterative server configuration
  • 📊
    Grafana Revealed Bottlenecks — dlib face detection caused P95 latency spikes
  • 🔐
    GitHub Actions Secrets — Far simpler than managing external CI credential stores
📌 Key Takeaway
Deploying a GPU-heavy ML app in a real DevOps pipeline forced confrontation with timeout tuning, volume management, probe configuration, and build caching — concerns absent from standard web deployments. The full automation from code push → Kubernetes pod → Grafana alert represents a production-grade DevOps pipeline.
